# Fix: Error 400 redirect_uri_mismatch en Google Sign-In

## Diagnóstico (verificado)
- En Android, `useGoogleAuth` resuelve `clientId = EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` (`15366859281-nec6...`) y `expo-auth-session` v54+ envía `redirect_uri = com.sui.app:/oauthredirect` (lo genera desde `Application.applicationId`; confirmado en `node_modules/expo-auth-session/build/providers/Google.js:145`).
- Google solo acepta `<package>:/oauthredirect` si el **OAuth Client tipo "Android"** en Cloud Console tiene registrado exactamente el package `com.sui.app` **y el SHA-1 de la llave que firma el APK instalado**. El 400 indica que no coinciden (o que corres en Expo Go, donde el package es `host.exp.Exponent`).
- Riesgo posterior: los client IDs son del proyecto GCP `15366859281` pero Firebase es `xsui-nica` (`332610869067`). Sin registrarlos en Firebase, el login fallará tras el OAuth con `auth/invalid-credential`.

## Pasos (mayormente en Google Cloud Console; sin cambios de código para el login Android)

### 1. Obtener el SHA-1 real de la app instalada
- Build local (`expo run:android` / gradlew, firma con `debug.keystore` según `android/app/build.gradle`): `keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android` → SHA-1 esperado: `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`.
- Build EAS: `npx eas credentials` (en `apps/mobile`) → ver SHA-1 del keystore gestionado por EAS.
- Si corres en **Expo Go**: no aplica tu keystore; se usa package `host.exp.Exponent` + el SHA-1 público de Expo Go.

### 2. Corregir el OAuth Client Android en Google Cloud Console (proyecto 15366859281)
- APIs & Services → Credentials → OAuth 2.0 Client ID `15366859281-nec6...`:
  - **Package name**: `com.sui.app` (idéntico a `app.json` → `android.package`).
  - **SHA-1**: pegar el SHA-1 del paso 1 (añadir debug y release/EAS si usas ambos).
- Si ese client ID resulta ser de tipo **Web** (no Android), crear uno tipo Android con los datos anteriores y actualizar `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` en `apps/mobile/.env`.

### 3. Registrar los client IDs externos en Firebase (proyecto xsui-nica)
- Firebase Console → Authentication → Sign-in method → Google → configuración del SDK web → **"Permitir IDs de cliente adicionales"**: añadir `15366859281-hjaskug...` (web) y `15366859281-nec6...` (Android).
- Esto sigue lo ya documentado en `docs/how-to/complete-cloud-configuration.md:48`.

### 4. iOS (opcional, solo si pruebas en iOS)
- `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` está vacío → en iOS cae al Web client ID y fallará igual. Crear OAuth Client tipo iOS (bundle `com.sui.app`), setear la variable en `.env` y registrar el bundle en GCP. Requiere rebuild.

### 5. Verificación
- Los cambios de consola no requieren rebuild; solo si se cambia `.env`.
- Reintentar "Continuar con Google". En dev, `useGoogleAuth.ts:91-97` loguea `[Google Auth] Starting auth flow with: {clientId, redirectUri}` — verificar que `redirectUri` sea `com.sui.app:/oauthredirect` y `clientId` el Android ID.

### 6. Documentación
- Añadir en `docs/how-to/complete-cloud-configuration.md` (sección Google identidad) el redirect exacto de expo-auth-session v54+: `<applicationId>:/oauthredirect` requiere package+SHA-1 del APK instalado en el client Android.
